DonutREP 1.22.27 - ALL COMMANDS, with examples
========================================================================
186 commands, in 14 groups, sorted A-Z inside each group. Read it like this:
  <x> = you must type it      [x] = you may leave it out      a|b = pick one
  Steve / Alex are example player names. Amounts accept k, m, b, t (2.5k = 2500).
  'Aliases' are other names for the same command. 'Permission' is the node that lets a player use it
  (most staff and admin commands are for ops by default; give the node in LuckPerms to anybody else).
  This list is made from the plugin itself, so every command that exists is in it.

  COMMANDS THAT DO NOT WORK (checked by running every command once):
    /create               "This command is not configured on this server." - it does nothing (a placeholder from the original plugin).
    /sellall /sellhand /meta /limits   removed on purpose - they do not exist (selling is /sell and its menu; limits are in the LuckPerms section below).
    /shardshop /punishments            not registered (use /shop and /punishhistory).
    /pvp kit ...          "Kits are turned off" until ffa.yml -> ffa.kits-enabled is true.
    /ffa, /duel           need at least one enabled arena (/ffaarena, /arena) - without one they say so.
    /spawner list         the list menu is off by default (spawners.yml); /spawner panel works.

  IF A REGULAR PLAYER CAN USE AN ADMIN COMMAND: on a clean server none of the 96 admin commands can be used without a permission (tested with a player who is not op).
  So the player has the permission from somewhere else: a LuckPerms wildcard (*, donutrep.*) on a group, an exact node, or ANOTHER PLUGIN that has
  its own /fly, /gamemode ... (then DonutREP's command is not the one running). Find it:
    /donutrep perms <player>           - lists the admin commands the player can use and why (it also names plugins that took a command over)
    /lp user <player> permission info  - every permission and the group it comes from
    /lp user <player> permission check donutrep.command.fakeplayer   - where one node comes from
  Remove it:  lp group default permission unset donutrep.*     (or whatever the list shows)

/addmoney <player> <amount>
    Add Money to a player.
    Examples:  /addmoney Steve 10000
    Permission: donutrep.command.addmoney

/addshards <player> <amount>
    Grant Shards to a player (console command StoreBridge runs to deliver a package).
    Examples:  /addshards Steve 100
    Permission: donutrep.command.addshards

/balance [player]
    Check your Money balance, or another player's.
    Examples:  /balance
               /bal Steve
    Aliases:   /bal
    Permission: donutrep.command.balance

/pay <player> <amount>
    Send Money to another online player.
    Examples:  /pay Steve 500
               /pay Steve 2.5k            (k = thousand, m = million, b = billion, t = trillion work in every amount)
    Permission: donutrep.command.pay

/removemoney <player> <amount>
    Remove Money from a player.
    Examples:  /removemoney Steve 500
    Permission: donutrep.command.removemoney

/removeshards <player> <amount>
    Remove Shards from a player (console command StoreBridge runs on a chargeback).
    Examples:  /removeshards Steve 50
    Permission: donutrep.command.removeshards

/setmoney <player> <amount>
    Set a player's Money balance exactly.
    Examples:  /setmoney Steve 25000
    Permission: donutrep.command.setmoney

/setshards <player> <amount>
    Set a player's Shards balance exactly.
    Examples:  /setshards Steve 1000
    Permission: donutrep.command.setshards

/shardpay <player> <amount>
    Send Shards to another online player.
    Examples:  /shardpay Steve 25
    Permission: donutrep.command.shardpay

/shards [player] | /shards everywhere <status|debug> [player]
    Check your own Shards balance (no player lookup).
    Examples:  /shards
               /shards Steve
               /shards everywhere status
               /shards everywhere debug Steve
    Everywhere: donutrep.shards.everywhere (nobody has it by default, ops too): a rank with it earns a shard every minute anywhere. Without it shards come from the shard / afk cuboids.
    Permission: donutrep.command.shards

ORDERS

/orders [item] | my | collect | create <price> <amount> | fulfill <id> | cancel <id>      (also: /order)
    Post buy requests other players can fulfill, or fulfill/collect/cancel one. /order is the same command.
    Examples:  /orders                      (browse every open order)
               /orders diamond              (only orders for diamonds)
               /orders my                   (your own orders)
               /orders collect              (take the items that were delivered to your orders)
               /orders create 50 64         (a new order: pays 50 per item, wants 64 items)
               /orders fulfill 7            (deliver items to order #7 and get paid)
               /orders cancel 7             (cancel your order, unspent money comes back)
    New menus (orders.yml -> new-menus: true, the default): /orders my is "Orders -> Your Orders": your orders first (item, requested, price each, delivered, time until it expires), then a grey
               "New Order" slot for every slot you are allowed, then red "Locked" slots. Click an order: "Orders -> Edit Order" (the item, Cancel in the middle as a red block, Collect as a chest,
               Back). Cancel opens "Orders -> Cancel Order" (red = keep, green = confirm). A grey "New Order" slot opens the Choose Item window (icons), then the enchantment window (if
               enchantment orders are on, the default), then "How many?", "Price per item?" (shows the amount and the minimum) and "Review Order" (Cancel / Place Order); no chest menu opens.
               A wrong number brings the same window back with a red line. The board has no Collect button then (collect inside Edit Order, or /orders collect). new-menus: false = the
               original menus (the "Orders -> new order" chest window). Servers without dialogs (Spigot, CraftBukkit) always use the chest window.
    Expiry:    orders.expire-days (7): after that nobody can deliver to the order and it leaves the board; it stays, its owner can still collect and cancel (refund). orders.delete-days (90): an
               order not fully claimed by then is deleted - the part nobody delivered is refunded, delivered items nobody collected go with it. 0 = never. Orders from before the update are
               counted from the day of the update.
    Menu:      Sort and Filter work like in /ah (list of choices, left = next, right = previous), also in the
               "select item" menu of /orders create. The categories are the same as in /ah.
               The item list and /orders create only offer survival items (no spawn eggs, command blocks, barrier ...).
               Spawners cannot be ordered or delivered; /sell, /sellhand, /sellall and the sell menu refuse them too.
    Limits:    orders.yml -> orders: max-active-default: 5 (open orders per player without a permission), max-quantity-per-order: 2304,
               allow-enchant-orders: false. A player's limit is the highest number of their donutrep.orders.limit.<n> permissions.
    Permission: donutrep.command.orders

/ahstats
    Shows real Auction House activity - the highest-priced active listings.
    Examples:  /ahstats
    Permission: donutrep.admin.ahstats

/auctionhouse [sell <price>|my|history|buy <id>|cancel <id>]
    List, browse, and buy player-listed items on the Auction House. Staff with auctionhouse.admin can cancel anyone's listing.
    Examples:  /ah
               /ah sell 5000
               /ah my
               /ah history
               /ah buy 12
               /ah cancel 12
    Menu:      the Sort and Filter buttons list every choice with an arrow on the current one (like the filter of
               /playerranks): left-click = next, right-click = previous. Categories: All, Blocks, Tools, Food, Combat,
               Potions, Books, Ingredients, Utilities, Misc (spawn eggs, music discs, pottery sherds, smithing templates,
               banner patterns, bundles, keys). Spears, horse / wolf / nautilus armor and tipped arrows are Combat;
               minecarts, boats, maps, compass, saddle, name tag, item frames are Utilities.
    Survival:  only items that exist in survival can be listed: spawn eggs, command blocks, barrier, bedrock, infested blocks,
               debug stick and similar are refused (1.11.63). Spawners (from /shop or /spawner give) can NOT be listed, ordered or sold (1.11.64).
    Aliases:   /ah
    Permission: donutrep.command.auctionhouse

/billford
    Open the Billford trader
    Examples:  /billford
    Layout:    billford.yml: the confirm button is at slot 23 and the clock at 32 (both one slot to the right of before), the reward at 25, and the loot a
               trade asks for sits in a 3x3 block (slots 10-12, 19-21, 28-30). An existing billford.yml keeps its old numbers - change CONFIRM_SLOT,
               COUNTDOWN_SLOT and the SLOT of each input, or delete the file to get the new one.
    Permission: donutrep.command.billford

    Permission: donutrep.command.sell

    Examples:  /sellall

               /sellhand 16
    Permission: donutrep.command.sellhand

/sellhistory

    Examples:  /sellhistory
    Permission: donutrep.command.sellhistory

/sellmulti [category]
    Sell a specific amount of a specific material from your inventory.
    Examples:  /sellmulti
               /sellmulti <category>
    Note:      the multiplier of a category also applies to the SELL ALL button in a spawner's storage menu, and what
               you sell there counts towards the next level, exactly like /sell (new in 1.11.57).
               10 categories since 1.11.62: Crops, Ores, Mobs, Natural Items, Armor And Tools, Fish, Enchanted Book,
               Potions, Blocks (real blocks only) and the new Miscellaneous (every item that is not a block and fits
               nowhere else: music discs, dyes, pottery sherds, smithing templates, banner patterns, bundles, boats,
               minecarts, buckets, maps, compass, clock, name tag, lead, paper, spawn eggs, written book ...).
               Moved in 1.11.62: spears, horse / wolf / nautilus armor, harnesses, saddle, shears, brush, flint and steel
               -> Armor And Tools; flowers, grass, ferns, vines, roots, moss, mud, snow, soul sand, fungi, mushroom
               blocks -> Natural Items; golden apples, stews, soups, cake, bone meal -> Crops; scutes, blue / brown egg,
               goat horn, tipped arrows -> Mobs; fish buckets -> Fish; experience bottle, glowstone dust -> Potions.
               A moved item uses its new category's multiplier from the next sale; progress already earned stays where
               it was. Prices, enchanted books and renamed / anvil-used items (amethyst tools) are unchanged.
    Progress:  click a category: "<NAME> PROGRESS" with the category icon top left and one pane per level along a winding path - green COMPLETED,
               yellow IN PROGRESS, gray LOCKED. The tooltip shows the bar, 'x1.05 100.0%' and 'earned/needed' (e.g. 30.0K/25.0K).
    Permission: donutrep.command.sellmulti

/sellmultiplier [category]
    View, or (admin) set, the global sell-price multiplier.
    Examples:  /sellmultiplier
               /sellmultiplier <category>
    Permission: donutrep.command.sellmulti

/sellprogress [category]

    Examples:  /sellprogress
               /sellprogress <category>
    Permission: donutrep.command.sellprogress

/setafk <cuboid> [point number]
    (admin, 1.11.99) Add a teleport point to an AFK cuboid at the place where you stand. With a number it moves that point instead. There is no limit on the
    number of AFK cuboids; every cuboid keeps its own points (up to areas: max-points, 20). A cuboid that is not an AFK cuboid yet becomes one. Players who go to the
    cuboid (/afk) land on one of its points - a random one, or one after the other (set it per cuboid in /afkmenu; areas: point-mode is the default).
    Examples:  /setafk afk1                 (point 1, then 2, 3 ... of the cuboid afk1)
               /setafk afk1 2               (move point 2 to where you stand)
    Before 1.11.99 /setafk forced a player's AFK status: that is /forceafk <player> [on|off] now (and /setafk zone is /forceafk zone).
    Permission: donutrep.admin.cuboid

/forceafk <player> [on|off] | /forceafk zone
    (admin, 1.11.99) Force another player's AFK status on or off (this was /setafk before 1.11.99; /forceafk zone is the old /setafk zone).
    Permission: donutrep.command.setafk

/afkmenu
    (admin, 1.11.99) A menu with all AFK cuboids (name, world, number of points, players inside); click one to edit it: every teleport point is an ender pearl
    (left-click = teleport there, shift-click = move it to where you stand, right-click = delete it), Add a point (where you stand), how players are sent (random /
    one after the other), and an on/off button for the cuboid. The nether star at the end of the list makes another cuboid an AFK cuboid.
    Permission: donutrep.admin.cuboid

/spawnmenu
    (admin, 1.11.99) The same editor for the spawn cuboids (what /spawn sends players to). /setspawn <cuboid> [point number] adds or moves a spawn point;
    /setspawn alone still sets the server's spawn point.
    Permission: donutrep.admin.cuboid

/setkey <cuboid> [point number]
    (admin, 1.15.0) Adds a teleport point for a KEY-ALL cuboid where you stand (with a number: moves that point). The first point also makes the cuboid a key-all area.

    (1.15.1) /setkey, /keymenu and /keyafk (and the keyall choice of /cuboid bind) only exist while keyall.yml -> afk-only or cuboid-only is true. With both false they are hidden from tab-complete for everybody (ops too) and refuse to run. Key-all for everyone is not affected.

/pregen [start <world> [radius|border] [centerX centerZ]|pause|resume|stop|status]
    (admin, 1.11.97) Make the land of a world ahead of time, like the Chunky plugin. <world> is the real name of the world: world, world_nether, world_the_end ...
    It starts at the centre and walks outwards region by region; chunks that already exist are skipped (so it carries on where Chunky stopped), new ones are asked for
    a few per tick. The speed is limited by the server's world generation: it will not beat Chunky by much (16 new chunks per tick, 64 at once, per world).
    Examples:  /pregen start world                     (the radius of the border: 200000 around 0,0)
               /pregen start world_nether 50k 0 0      (radius 50000, 1000 or 1k works too)
               /pregen status                          (percent, chunks made / already there, chunks per second, a time left that is at most)
               /pregen pause all | /pregen resume world_the_end | /pregen stop world_nether     (stop forgets the task)
    Console:   every 5 minutes (border.yml -> pregen: log-minutes) a line like Chunky's:
               Task running for world_the_end. Processed: 152727325 chunks (97.73%), ETA: 13:12:54, Rate: 74.6 cps, Current: -6149, -1329
               (Current = the chunk the walk has reached; the ETA counts every chunk left as new, so it can be too long where many chunks exist already.)
    Discord:   discord.yml -> discord: pregen: webhook-url (blank = off), every-percent: 10 (a message at 10%, 20% ... 0 = none), on-start, on-finish, username.
               A message also goes out when a task is paused because its world is not loaded.
    Safety:    nothing is asked for while the TPS is under 17, at most 64 chunks per world are being made at once. The progress is saved every 30 seconds in data2/pregen-state.yml;
               after a restart the task waits paused - /pregen resume carries on (pregen: auto-resume: true does it by itself). One task per world; the worlds can run together.
    Settings:  border.yml -> pregen: enabled, chunks-per-tick, max-in-flight, min-tps, skip-check (status = reads each saved chunk and counts only finished ones, header = only looks at the region file list), save-seconds, log-minutes, auto-resume
    Note:      the game saves half finished chunks around every chunk it makes. skip-check: status (the default) looks into each saved chunk and finishes those; on a huge old world that
               means reading every chunk once (hours, in background threads). skip-check: header only looks at the region file list (minutes) and treats half finished chunks as done.
    Permission: donutrep.admin.pregen

========================================================================
LUCKPERMS: LIMITS (homes, auction house, orders)
========================================================================
Players get limits from permissions, the HIGHEST number a player has wins (a lower one cannot lower it). Without any, the default applies:
homes 3 / auction listings 5 (plus.yml -> limits.defaults) and orders 5 (orders.yml -> orders.max-active-default). A lower limit never deletes
anything that already exists. Use  lp user <name> ...  for one player or  lp group <group> ...  for a whole rank. Every number can be anything (1, 7, 25, 100).

  HOMES  (/sethome, /homes)            node:  donutrep.homes.<n>
      lp user Steve permission set donutrep.homes.10 true
      lp group vip permission set donutrep.homes.15 true
      lp group mvp permission set donutrep.homes.30 true
      lp user Steve permission unset donutrep.homes.10          (take it away again)

  AUCTION HOUSE  (/ah sell)            node:  donutrep.auctionhouse.<n>      (listings at the same time)
      lp user Steve permission set donutrep.auctionhouse.20 true
      lp group vip permission set donutrep.auctionhouse.25 true
      lp group mvp permission set donutrep.auctionhouse.50 true
      lp user Steve permission unset donutrep.auctionhouse.20

  ORDERS  (/orders create)             node:  donutrep.orders.limit.<n>      (open orders at the same time)
      lp user Steve permission set donutrep.orders.limit.10 true
      lp group vip permission set donutrep.orders.limit.15 true
      lp group mvp permission set donutrep.orders.limit.25 true
      lp user Steve permission unset donutrep.orders.limit.10

  CHECK what a player has:  lp user Steve permission info   (also look at their groups: lp user Steve info)
  A temporary limit:        lp user Steve permission settemp donutrep.homes.20 true 7d
  Defaults (everybody):     plus.yml -> limits: defaults: homes: 3 / auction: 5 / orders: 5   (orders: orders.yml max-active-default wins)
  The prefix donutrep. works in front of every node:  donutrep.homes.10 and donutrep.homes.10 are the same.
  The nodes of other features (staff, admin, bypass) are in each command above under 'Permission:'.
  All of them at once for an admin group:  lp group admin permission set donutrep.* true

    Reach (A)       the distance from the attacker's eyes to the nearest side of the target's box (3.0 + leeway 0.6 + ping)
