DonutREP 1.22.27 - WHERE TO EDIT WHAT
========================================================================
Every setting of the plugin is in a yml file in plugins/DonutREP/. This file tells you which one, so you never have to search.
After you change a yml file, run  /donutrep reload  (it reads every file again). A few timers are only read at start (the text says so).
This file is written automatically at every start. Do not edit it; your own notes go in your own file.

How to read an entry:    file -> key: default value   what it does
  A key with dots is a path:  keyall.area-percent  means the line  area-percent:  inside the block  keyall:  in keyall.yml.
  true / false switches: true = on.   Every feature of the plugin has its own switch, listed below and in the index at the end.

KEY-ALL  (keyall.yml)
------------------------------------------------------------------------
  Turn key-all on / off ............ keyall.yml -> keyall: enabled: true
  How often ........................ keyall: every-minutes: 60                (the timer is read at start; restart after changing it)
  Which key ........................ keyall: type: RANDOM  (a key is rolled from random-keys)  or  ONE  (always one-key)
                                     one-key: common        random-keys: {common: 80, rare: 15, epic: 5}  (weights)
  How many keys per round .......... keyall: amount: 1
  Which crate a key gives .......... keyall: tier-crates: {common: common, rare: rare, epic: epic}
  Add or rename a key .............. add a line under random-keys and tier-crates. The NAME MUST BE A CRATE THAT EXISTS (see /crate). If it is not, the console and every online
                                     op / staff member get a warning naming the key, and that key is not given until you fix it. (keyall: warn-staff: true)
  The message players get .......... keyall: message: [...]
  WHO GETS THE KEY  (the same key in every mode; only one mode can be on):
      everybody online ............. keyall: afk-only: false   and   cuboid-only: false   (the default)
      only players in an AFK cuboid  keyall: afk-only: true
      only players in a key-all cuboid   keyall: cuboid-only: true     (make the cuboid: see below)
      both true = the round is skipped and a warning is logged.
  A TIMER for the area modes ....... With afk-only or cuboid-only on every player in the area has a timer of their own (starts when they enter, restarts when they leave or rejoin). keyall: area-match-shards: true = as long as the shard timer where they also earn shards; area-actionbar: true = "Next Key in ..." in the action bar (cuboid-only mode)
  A CHANCE for the area modes ...... keyall: area-percent: 100   (0-100). With afk-only or cuboid-only on, every player standing in the area rolls their own chance when their timer ends:
                                     100 = everybody in the area gets the key, 50 = each has a 50% chance. Not used when both switches are false.
  Give a key to everybody online right now (no timer)  /crate keyall <crate> <amount>

------------------------------------------------------------------------
KEY-ALL AND AFK CUBOIDS
------------------------------------------------------------------------
  Make a cuboid ................... /cuboid wand  (select two corners), then  /cuboid create <name>
  Make it a KEY-ALL area .......... /cuboid bind <name> keyall true       (false removes it; /cuboid unbind <name> keyall)
  Make it an AFK area ............. /cuboid bind <name> afk true          (an AFK area also earns shards: see GETTING KEYS / SHARDS WHILE AFK)
  Teleport points of a key-all area  /setkey <name>  adds a point where you stand,  /setkey <name> 2  moves point 2,  /keymenu  is the editor (list, add, move, delete, teleport,
                                     random or one after the other, on/off). Same for AFK:  /setafk <name>  /afkmenu   and spawn:  /setspawn <name>  /spawnmenu
  How many points a cuboid can have  plus.yml -> areas: max-points: 20       how players are sent: areas: point-mode: random  (or  order)
  Show the cuboid names in the menus plus.yml -> areas: show-names: false
  (1.15.1) /setkey, /keymenu, /keyafk and the keyall cuboid bind are only there while keyall.yml -> afk-only or cuboid-only is true; with both false they are hidden and off.
  Where players go to stand in the key-all area  /keyafk  (a menu, like /afk and /spawn).  Switch it off: plus.yml -> features: keyafk: false
  Where the points are saved ...... cuboids.yml -> <cuboid>: points: keyall   (edit with the menus, not by hand)

------------------------------------------------------------------------
GETTING KEYS / SHARDS WHILE AFK
------------------------------------------------------------------------
  KEYS in an AFK area ............. keyall.yml -> afk-only: true  (+ area-percent for the chance). Needs an AFK cuboid:  /cuboid bind <name> afk true
  SHARDS in a shard / AFK cuboid .. plus.yml -> zones: shard: interval-seconds: 60   amount: 1   recent-movement-seconds: 0  (0 = idle players earn)   reset-on-leave: true
                                     Bind:  /cuboid bind <name> shard true   (or afk)
  AFK status of a player .......... config.yml -> afk: timeout-seconds: 300  (idle time before a player counts as AFK)
  Kick AFK players ................ config.yml -> afk: kick: enabled: false   after-seconds: 1800
  "X is now AFK" chat message ..... plus.yml -> afk: announce: false
  The /afk menu and its points .... /afkmenu, /setafk <cuboid>     (points are in cuboids.yml)

------------------------------------------------------------------------
SPAWNERS  (spawners.yml)
------------------------------------------------------------------------
  Storage spawners (no mobs; loot fills a menu)  or  real mobs like vanilla - choose ONE:
      spawners.yml -> SETTINGS: STORAGE_SPAWNERS: true      MOB_SPAWNERS: false
      (both true or both false = an error in the console and storage mode is used)
  Stop spawners spawning mobs ..... keep  STORAGE_SPAWNERS: true  and  CANCEL_MOB_SPAWN: true  (managed spawners then never spawn a mob)
  Let spawners spawn mobs ......... MOB_SPAWNERS: true  (STORAGE_SPAWNERS: false). Stacked spawners add mobs: MOB_STACK_MULTIPLIER: true, MOB_STACK_MAX_EXTRA: 15
  Turn the whole spawner system off  SETTINGS: ENABLED: false
  Old vanilla spawners become managed  SETTINGS: MANAGE_VANILLA_SPAWNERS: true  (this line is not in the file by default; add it under SETTINGS to change it - a spawner that tries to spawn is registered)
  How fast loot is made ........... GENERATION_INTERVAL_SECONDS: 5  (read at start)       only near players: REQUIRE_PLAYER_NEARBY: false   PLAYER_NEARBY_RADIUS: 16
  Stack limit / storage limit ..... MAX_STACK_PER_BLOCK: 100000    STORAGE_CAP_PER_LOOT_KEY: 1000000
  Loot of each spawner type ....... spawners.yml -> TYPES: <TYPE>: DROPS  (material, chance, min, max)    BASE_ITEMS_PER_CYCLE
  Spawner shop prices ............. spawners.yml -> SHOP: CURRENCY: SHARD   DEFAULT_PRICE: 1500   PRICES: {PIG: 1000}
  Silk Touch needed to pick one up  REQUIRE_SILK_TOUCH: true
  Players can switch hostile mobs off near them  /settings -> Disable Mob Spawn (player-settings.yml)
  Hide spawners from far away (anti-ESP) ... antiesp.yml (next section)

------------------------------------------------------------------------
ANTI-ESP  (antiesp.yml)   spawners and chests far from a player look like plain blocks
------------------------------------------------------------------------
  Switch it on / off .............. antiesp: enabled: true   (ON by default)
  What it hides ................... spawners: enabled: true   chests: enabled: true   chests: types: [CHEST, TRAPPED_CHEST, BARREL, ENDER_CHEST]
  The radius ...................... spawners: radius: 24   chests: radius: 24   (blocks; a sphere around the player). Inside it the player sees the real block, farther away the disguise.
  What the disguise looks like .... antiesp: disguise: deepslate-below-y: 0      below this height -> deepslate
                                                       stone-below-y: 60            from there up to this height -> stone
                                                       above-block: CRAFTING_TABLE  anywhere else (higher up, the Nether, the End)
  Worlds where nothing is hidden .. antiesp: excluded-worlds: []
  How often distances are checked . antiesp: check-ticks: 10     (20 ticks = 1 second)
  The strong mode ................. antiesp: packets: true  - with the packetevents plugin the chunk packets are rewritten before they are sent (a cheat client never receives
                                     the real block). Without packetevents (or packets: false) plain block changes are sent after the chunk: weaker.
  Staff who must see everything ... give the permission  donutrep.bypass.antiesp   (ops do NOT have it) - or  antiesp: ops-bypass: true  lets every op see the real blocks
  See what it does right now ...... /donutrep antiesp      and  /donutrep antiesp check <player>  (why that player sees what they see)
  Limits: a block that changes in groups (explosions, pistons, WorldEdit) can show its real block for a moment; a cheat client that reads the raw network data in the plain mode can see it.

TEAMS  (teams.yml)
------------------------------------------------------------------------
  All of these are OFF by default except the leaderboards. The TEAM LEADER uses them.
  Rename the team ................. teams.yml -> teams: rename: true      then  /team rename <name>  or  /team -> Team Settings -> Rename Team
  Team color ...................... teams: color: enabled: true           then  /team color <name or #rrggbb>  or the color picker in Team Settings.
                                     The team line of the scoreboard uses the color.
  Team icon (like homes) .......... teams: icons: true                    then  /team icon  or  Team Settings -> Team Icon   (shown in the team menu and the list of teams)
  Allies .......................... teams: allies: enabled: true   max: 3   then  /team ally <team>  (the other leader accepts:  /team ally accept <team>),  /team ally remove <team>
                                     Allied teams cannot hurt each other (like teammates).
  Leaderboards .................... teams: leaderboards: true    leaderboard-size: 10    leaderboard-cache-seconds: 60
                                     /teamtop  (menu: most kills, deaths, playtime, money, shards)    /teamtop kills   (also /teambaltop, /teamshardstop)
  Teammates cannot hit each other . plus.yml -> features: team-pvp-lock: true   (/team pvp turns it on)
  Team data (home, permissions, color, icon, allies) is in team-settings.yml - do not edit it by hand.

SHOP MODES  (quickshop.yml)   /shop is one command with three shops
------------------------------------------------------------------------
  Pick ONE ........................ quickshop.yml -> quickshop: classic: true (the normal /shop, the default)   auction: false (QuickShop)   survival: false (every survival item)
                                     More than one true: every admin gets a red message in chat and /shop stays closed for everybody until it is fixed (change it, then /donutrep reload).
  QuickShop (auction: true) ....... /shop shows the items a player saved; one click buys the cheapest matching listings from /ah (the real /ah purchase: the seller is paid, the listing is gone).
                                     quickshop: auction-shop: confirm: false              true = a confirm window always opens first (players cannot turn it off)
                                                               allow-bigger-listings: false   /ah sells a whole listing: false = a listing bigger than the amount still needed is skipped
                                                               max-items: 45              dialogs: true   (false = chest menus; Spigot and CraftBukkit always use chest menus)
                                     Every player can turn auto buy off for themselves:  /settings -> Player -> QuickShop Auto Buy.   Saved items: data2/quickshop-data.yml (do not edit by hand).
  Survival shop (survival: true) .. every item a survival player can get, in the categories of the creative inventory; price = the /sell worth x the highest sell multiplier the server allows (2.0) x  quickshop: survival-shop: times-max-sell: 2.0  (= 4 x the worth)
                                     max-per-purchase: 64.   The first menu also has Crate Keys and the Shard Shop (spawners): they open the classic menus, so their items and prices are in shop.yml.
                                     The items of a category are organized (logs together, leaves together; Building Blocks by type: all planks, then all stairs, slabs, walls, fences ...); the filter Name (A-Z) sorts them by name.
                                     An enchanted item costs (its worth + its enchantments, see enchant-worth.yml) x the same multiplier. Dialog windows: quickshop: dialog-columns: 3 (the Choose Item list; 4 on a small GUI scale, 2 on a big one).
  Homes as dialog windows ......... dialog.yml -> dialog: homes: enabled: false (true = /home and /homes open dialog windows; Paper only)   columns: 4   max-slots: 9 (Show More)   confirm-delete: true   icons: true (Change Icon)   icon-columns: 3 (Choose Icon list)   team-home: false (true = a Team Home button; false = team homes off while the dialog is on)
                                     How many homes a player may have: the permission donutrep.homes.<n> and limits.defaults.homes (plus.yml). A higher rank unlocks more slots. The dialog has its own icon switch (icons), features.custom-icons is for the chest menus.
  Enchantment worth ............... enchant-worth.yml -> enchant-worth: enabled: true   default-per-level: 0 (for an enchantment that is not listed: 0 = the Enchanted Book worth, 16)   per-level: every enchantment by rarity (common 10, uncommon 20, fortune 50, silk touch 120, mending 300 ...)
                                     An enchanted item has ONE worth = the item + every enchantment level. Shown on hover, paid by the /sell menu and the sell chest axe (x your sell multiplier), asked by the survival shop (x the shop multiplier).
                                     Admins (op or donutrep.admin.shop): the stick in the shop = edit mode, click an item to take it out of the shop (the list closes up); the Removed Items button puts items back.
                                     The removed items are saved in data2/survival-shop.yml (do not edit by hand).

SELL HOE and the other amethyst tools  (amethyst-tools.yml)

LANGUAGES  (language.yml, the languages folder)
------------------------------------------------------------------------
  What it is ...................... every player has their OWN language. They pick it whenever they like: /language (or /lang) opens a window with Automatic and the languages; /language <code> or /language auto sets it directly.
                                     Nobody has to choose when they join. The choice is saved per player in data2/player-language.yml (do not edit by hand).
  Switches ........................ language.yml -> language: enabled: true (false = nothing is translated, /language says it is off)
                                     default: en (the language everybody starts on; any code of a file in the languages folder)
                                     auto-detect: true (a player who has not chosen starts on their Minecraft client language when there is a file for it)
                                     force: false (true = everybody sees the default language and /language is turned off)
  The files ....................... languages/<code>.yml: 13 packaged (en + Spanish, Portuguese (Brazil), French, German, Russian, Turkish, Polish, Italian, Dutch, Chinese (Simplified), Japanese, Korean).
                                     Every line is  "English text": "translation".  Keep the {0} {1} ... (the parts that change) and the & colour codes. Delete a line to leave that text in English.
                                     The translations are machine quality - have a native speaker read the files you care about.
  Add your own language ........... copy languages/en.yml to languages/<code>.yml, change code: and name:, translate the right side, then /donutrep reload. It shows up in /language by itself.
  Updating ........................ a packaged file you edited is never overwritten. If a new plugin version ships a file with a higher version: number, the new one replaces yours and yours is kept as <code>.yml.old.
  What is translated .............. shops (/shop, survival shop, QuickShop), homes and warps, orders, /ah and /sell, friends, /settings, sell progress, teams (menus and messages), crates, arenas, portals, spawners,
                                     RTP, staff and admin menus and messages, the sidebar scoreboard lines and the tab list header and footer, and the dialog windows. Messages with a click or hover button (like the
                                     [ACCEPT] [DENY] of a friend request) are translated too and the buttons keep working. en.yml lists every text that can be translated.
  NOT translated .................. Minecraft's own text (it follows the game language), other plugins, messages of the original plugin that are not written by DonutREP+, and any line you reworded yourself in a yml
                                     file (scoreboard.yml, tablist.yml, messages.yml ...): to translate your own wording add  "your English line": "translation"  to the language file (a part that changes is {0}, {1} ...).  Needs ........................... packetevents for chat, menus and titles (dialog windows are translated without it).

------------------------------------------------------------------------
IMPORT OLD DATA
------------------------------------------------------------------------
  /donutrep import <v1|v2> <folder> <preview|confirm> [replace] [again]     switch: plus.yml -> features: import: true     permission: donutrep.admin.import
  preview counts only; confirm backs up first (plugins/DonutREP/imports/<date>/) and imports. DonutREP's own data is kept unless you add replace.
  What comes over: balances, shards, homes (with their icons), warps, teams (home, friendly fire, member permissions), friends, bounties, ender chests, auction listings and their claims,
  orders (open ones keep their waiting items; refunds are paid once), QuickShop saved items, duel and FFA stats, sell history and totals, and the Minecraft stats files (kills, deaths, playtime).
  A second run with again adds nothing twice.

------------------------------------------------------------------------
THINGS PLAYERS CAN SWITCH IN /settings
------------------------------------------------------------------------
  Stored in player-settings.yml (per player). The default of a switch is in the plugin; a player's own choice wins. Page 1: gameplay, scoreboard lines, Disable Mob Spawn, Night Vision ...
  Page 2: chat, messages and alerts. The server can switch off the whole scoreboard-line group with scoreboard.yml -> player-line-switches: false.

------------------------------------------------------------------------
TURN A FEATURE OFF  (plus.yml -> features:)
------------------------------------------------------------------------
  Every command group has a switch in plus.yml under  features:   (true = on).  A switched-off command tells normal players it is disabled; ops can still use it.
  Some examples:  features: keyafk, import, license, afk, cuboid, spawn, rtp, sell, team, leaderboards, crate, shop, tpa, duel, friends ...
  The complete list is in the index below (plus.yml -> features).

------------------------------------------------------------------------
PERMISSIONS
------------------------------------------------------------------------
  Commands:   donutrep.command.<command>      Admin:   donutrep.admin  (everything)   donutrep.admin.<thing>      Bypass:   donutrep.bypass.<thing>  (for example donutrep.bypass.antiesp)
  Per-player limits: donutrep.homes.<n>, donutrep.auctionhouse.<n>, donutrep.orders.limit.<n>, donutrep.enderchest.pages.<n>
  Why can this player use that command?  /donutrep perms <player>
  The complete list of commands with their permissions is in commands.txt (same folder).
